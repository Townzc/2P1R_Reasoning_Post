## 1. 必须修改

### F1（阻断 base 相关的一切评测）停止 token 没有覆盖模板的结束符

- 发布版 LLaMA-Factory 里，`qwen` 和 `llama3` 模板的 `replace_eos` 都是默认的 False。训练目标以模板结束符收尾（Qwen：`<|im_end|>\n`；Llama：`<|eot_id|>`），**不会**再接分词器的 EOS，保存的分词器 EOS 也不变。
- `evaluation.py` 的停止集合只取"分词器 EOS ∪ generation_config 的 EOS"。
  - Instruct 模型没问题：两者已包含 `<|im_end|>` / `<|eot_id|>`。
  - **base 模型及由它训练出的检查点有问题**：按我对这两个仓库的了解，Qwen2.5-1.5B base 的两处 EOS 都只有 `<|endoftext|>`，Llama-3.2-1B base 只有 `<|end_of_text|>`（请 Codex 用已下载文件确认）。SFT 后的模型输出 `<|im_end|>` 或 `<|eot_id|>` 时不会停，会一直生成到 16K 上限。
- 这正是 P011 那类"停不下来"的失败，会让主网格里 4 个 base 设定全部作废，并且白花生成费用。
- **修改**：
  1. `EvalConfig` 增加必填字段 `template_family`（`qwen` / `llama3` / `none`）。停止集合 = 现有集合 ∪ 该模板 `stop_words` 对应的 token id（Qwen：`<|im_end|>`；Llama：`<|eot_id|>`、`<|eom_id|>`）。
  2. `native_eos` 改名或拆成两列：`stopped_on_terminator`（命中上述任一 id）和具体的 `stop_token_id`。
  3. 加测试：对四个主网格分词器，断言模板结束符的 id 在停止集合里。

### F2 Llama 默认 chat 模板里的日期会随运行日变化

- Llama-3.2 分词器自带的模板会插入 `Today Date`，新版 transformers 下取当天日期。同一配置隔天运行，输入 token 就不同。
- **修改**：G0 中凡是用分词器默认模板的 Llama 评测，调用 `apply_chat_template` 时显式传 `date_string="26 Jul 2024"`（模板自己的回退值），并写进 manifest。主网格用导出的训练模板，不受影响。

### F3 生成批大小

- 现在每 16 条调用一次 `llm.generate`，vLLM 的连续批处理基本用不上。完整 MATH test 有 5,000 题、40 多个检查点，这会明显拉长 GPU 时间。
- **修改**：`batch_size` 默认改为 1024（或一次提交全部），仍按块落盘。

### F4（C8 前）主网格的模板一致性

- 发布版 `qwen` 模板训练时的系统提示是 "You are a helpful assistant."；Qwen 分词器自带模板是 "You are Qwen, created by Alibaba Cloud. …"。`llama3` 训练模板没有系统段；Llama 自带模板会加日期系统段。
- G0 保持这种不一致，因为 Li 的发布流程就是这样（训练用 LLaMA-Factory 模板，评测用分词器模板）。
- 主网格必须一致：
  1. `protocol == "omi2"` 时，`chat_template_file` 必填，否则报错；
  2. 加一个 token 级测试：同一道题，评测端渲染出的 prompt token 与 LLaMA-Factory 模板编码出的 prompt 部分完全相同（四个主网格模型各一例）。

### F5（C8 前）OMI-2 协议下 GSM8K 的数值判分过严

- 实测：`\$18`、`18\%`、`\text{18}` 对标准答案 `18` 都判错。P008–P009 的教训就是严格解析器会压低分数。
- **修改**：先用现有严格数值比较；不相等时再用 math-verify 判一次（它能处理 `\$18`）。记录每条是哪条路径判对的，并报告两种口径的差。`18 dollars` 这类仍判错，计入格式不合规。

## 2. 首次 GPU 运行时的检查（S1–S4）

G0-E 第一个模型跑前 20 题，检查通过后再跑全量：

- **S1**：`unclassified_stop == 0`；每条记录恰好属于"命中结束符 / 命中停止串 / 到达长度上限"之一。
- **S2**：`n=4` 采样时，同一题的 4 条输出不是完全相同的。
- **S3**：输出文本末尾没有残留的特殊 token 字符串。
- **S4**：`pre-rendered prompt` 路径用 `add_special_tokens=False`。Llama 的 few-shot 纯文本提示必须自己带 `<|begin_of_text|>`，否则没有 BOS。请在 base few-shot 输入构建处加断言。
