## 二、决定：选项 2（一次有界续跑），附条件

**理由**：B1、B3 在冻结计划 §7.3 中属于"不可砍"。失败原因明确且很窄，已有的 1,280 条输出可以原样保留；用实测数据估计，时间和预算都还有余量。如果下列任一条件做不到，就按选项 1 关闭 B，见第五节。

### 2.1 未映射 ID 的处理规则（新代码，必须 CR）

记 M = 分词器映射的 151,665 个 ID，V = 151,936。

1. 所有 ID 都在 M 中的行：原规则不变。
2. "无 EOS、长度 1024、finish = length"并含未映射 ID 的行：原例外不变，仍不可用。
3. **其他所有含未映射 ID 的行（新类别）**：
   - 记 p 为第一个未映射 ID 的位置。要求 p 在第一个原生 EOS（151645/151643）之前；否则 fail-closed，不得续跑；
   - 逻辑记录为 `stop_reason = 'invalid_special_token'`，`retained_tokens = p+1`，`answer_segment = decode(ids[:p])`。不解码跨过或绕过该 ID，也不删除它；
   - 原始 token 和后端元数据原样保存。另加字段 `unmapped_model_token_ids`、它们的位置，以及 `unmapped_noncap_invalid: true`；
   - 评分走冻结评分器中已有的 `invalid_special_token` 分支（P009/P010 `math_scoring.decide`）：不做符号比较，`teacher_label_eligible = False`。**报告中必须写明这些是"无法验证"，不是"已证明答错"**。
4. **训练文本排除**：任何含未映射 ID 的行（第 2、3 类）都**不能**以任何角色进入训练数据，包括 K = 1 的"16 次都不可用"回退。`short_generation.select` 现在的回退是固定取 `attempts[1]`，必须改为"按尝试顺序取第一条不含未映射 ID 的行"。若 16 条都含未映射 ID，该题从 K = 1 中缺席并报告（实际上几乎不可能）。实际输入 A1 要证明训练数据里含未映射 ID 的行数为 0。
5. **依据**：P010 E3 用的是同一个 T1.5 教师、T = 1.0、同一 seed 函数，已审计的 1,600 条中有 13 条 `invalid_special_token`，就是按这个"不可用、不验证"的口径处理的。新规则只是把同一口径扩展到比特殊 token 离文本更远的填充行 ID。
6. **分母**：主口径把这些行算作"已尝试、不可用"（与 E3 一致）；同时报告把它们剔除出分母的敏感性结果，并报告每批的行数。

### 2.2 续跑的范围

### 2.3 时间窗（负责人委托下的有界调整，附数值依据）

- **评分上限从 62,000 s 降到 7,200 s**。
  - 原 62,000 s 是 1.2 × (6,400 × 8 s + 300) 的技术假设，**不是实测**。
  - 实测依据：P010 E3（同一教师、同一温度）已审计的评分行中，T1.0 的 1,033 个符号比较对单对耗时最大 **0.068 s**、合计 3.8 s；T0.6 的 1,545 对最大 0.068 s。即使有 10% 的行（640 行）触发 8 s 的单对硬超时，总计约 640 × 8 + 5,760 × 0.1 ≈ 5,700 s，仍低于 7,200 s。
  - 条件：续跑的 A2-lite 必须给出 E3 评分阶段的实际墙钟时间 W（3,200 行），并满足 2W × 10 ≤ 7,200，即 W ≤ 360 s。不满足时要提出新的数值依据，不得自行放宽。
  - 评分代码 `b_score_process`/`b_scoring` 本来就接受 ≤ 62,000 的任意整数上限，不需要改代码。
- 其余保持不变：startup 600、platform 1,860、worker 1,800、collect 3,600、audit 3,600、cleanup 5。完整窗口 = 600 + 1,860 + 3,600 + 3,600 + 7,200 + 5 = **16,865 s**。按窗口本身，最晚可在 10/22 00:18 UTC 派发。
- **实际截止时间：10/21 14:00 UTC**。续跑如果在这之前还没通过 CR/A1/A2-lite 并派发，B 就关闭。原因是 B1、B3 学生要在生成评分完成后，还能放进它们自己的完整窗口（截止 10/22 05:00 UTC）。学生的评分上限也可以按 P010 学生评分的实测值另行设定，在学生的 A2-lite 中审查。
- 初始预测：1.2 × (20 × 22.10 + 600) = 1,250 s ≤ worker 1,770 s ✓ 实测每批约 16 s，会更快。
