## 4. 必须修改

### T1 主网格训练速度（阻断 C8）

**实测**：R1 在 H100 上 1.73 秒 / 步（每步 = 4 个大小为 2 的小批），648 步用了 20 分钟。

**推算**：主网格每个满算力格是 1,024 步，约 30 分钟、$2.2。Tier 1 有 32 个满算力格加 8 个低预算格，训练费用约 $72，而 Tier 1 的上限是 $30（还要包含评测）。

**修改（只针对主网格，在任何主网格训练之前）**：

1. `per_device_train_batch_size=8`，`gradient_accumulation_steps=1`。全局 batch 仍是 8，各格步数不变（1,024 / 128）。
   - 与原配置的差别：损失是 8 条样本的 token 平均，而不是 4 个"2 条平均"的再平均。写进 manifest 并在报告中披露。
2. 去掉 `skip_memory_metrics=False`。Trainer 的内存追踪会起一个不休眠的采样线程，拖慢训练。峰值显存改由启动器每 30 秒读一次 `nvidia-smi` 记录。
3. 梯度检查点保持默认（开启），保证最长序列凑在同一批时不会爆显存。
4. **费用探针**：C8 第一个设定先跑 L 格（128 步，最便宜），报告实测秒 / 步、峰值显存和整个 Tier 1 的预测，再放开其余格。
   - 预测（训练 + 评测）≤ $30：继续。
   - 超过：停下告诉我，备选是换更便宜的 GPU。
5. 所有训练一律 `modal run --detach`。

### T2 R1 / R2 的全局 batch：8 → 16

- 公开检查点的模型卡是那次训练自动生成的记录，写的是全局 batch 16。修订 1 的 M3 里"4 卡 → 全局 8"是从 YAML 推出来的，推错了。复现应以模型卡为准。
- R1 上一次在 648 步被网络中断，没有产生任何准确率结果，所以这是结果之前的更正。
- **修改**：R1、R2 用 `per_device_train_batch_size=2`、`gradient_accumulation_steps=8`（全局 16，约 666 步）。启动器的校验相应改为：复现格全局 16，主网格全局 8。同样去掉内存追踪。
- **主网格仍用全局 8**：这是我们自己设计里已冻结的量（1,024 步），不随复现格改。

### T3 R1 / R2 的 MATH-500 判定不再加载判分模型

- 依据 §3：两种口径相差不超过 0.4pp。
- R1、R2 报告"Li 精确匹配"和"精确匹配或 math-verify 等价"两个数；门槛（≤ 3pp）用后者对论文数字。省一次 H200 加载。
