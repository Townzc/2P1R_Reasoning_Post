## A6-2 Tinker：解答长度对照（探索性）

**要检验的解释。** seed 17 的结果里，训练后的准确率与初始化和数据量无关，输出长度都落到约 330 token；原本输出 800 token 以上、准确率 88–92% 的模型训练后掉到 66–71%。相容的解释是：SFT 让模型按教师解答的简短写法解题。这个解释还没有对照。

**设计。** 同一批题、同样的呈现次数，只换解答的写法。

| 臂 | 学生 | 训练解答 |
|---|---|---|
| 9B-短 | Qwen3.5-9B | OMI-2 解答（现有教师） |
| 9B-长 | Qwen3.5-9B | Qwen3.5-9B 自己的 0-shot 解答 |
| 4B-短 | Qwen3.5-4B | OMI-2 解答 |
| 4B-长 | Qwen3.5-4B | Qwen3.5-4B 自己的 0-shot 解答 |
| Base-短 | Qwen3.5-9B-Base | OMI-2 解答（用 9B 的题集） |
| Base-长 | Qwen3.5-9B-Base | Qwen3.5-9B 的 0-shot 解答 |

- 剂量：每臂 512 题 × 1 解 × 2 轮，batch 8，128 步，seed 17。配方与 T 轨的 L 格完全相同。
- 评测：完整 MATH 5,000，greedy，4,096 / 8,192，与 T 轨相同。

**长解答的生成与筛选（每个教师模型各做一次）。**

1. 题目：MATH 的 `training4096` 顺序，从第 1 题起依次处理。
2. 提示词：与评测相同的 OMI-2 0-shot、`qwen3_5_disable_thinking`、不带示例。
3. 每题最多 4 次：第 1 次 greedy；第 2–4 次 T=0.7，种子 `17 + 题号×4 + 次数`，每次单独调用。
4. 一条解答合格的条件：正常终止；最后一个 `\boxed{}` 与标准答案一致（现有评分器）；整条训练序列不超过 2,300 token（与 C6 的上限相同）。取第一条合格的。
5. 题集 M512：按顺序取前 512 道有合格长解答的题。没有合格解答的题跳过并记录。
6. 短解臂用同一个 M512，解答取 `P.jsonl` 里该题的那一条。
7. 训练文本：去掉生成结果末尾的结束符，由渲染器重新加上。

**冻结与核对。** 每个题集发布：长、短两份训练文件及 sha256、跳过的题号、每题用到第几次尝试、合格率、长短解答的 token 数分布。这是新的数据构建路径；考虑到金额小且时间紧，**本修订豁免事前审查**，改为我在结果审查时对全部长解答重新评分并核对题集一致性。Codex 自查以下各项，任何一项不满足就停：

- 长、短两份文件的题目集合和顺序完全相同，各 512 行；
- 每条长解答经现有评分器判为正确，且不含 `<think>`、不含结束符；
- 没有任何测试题或留出题进入训练文件。

**已知的混杂。** 两臂呈现次数相同，但长解臂每条的监督 token 更多。结果里同时报告呈现次数和监督 token 数。

**预测（在任何一臂评分之前冻结）。**

| 编号 | 预测 | 把握 |
|---|---|---:|
| LC-1 | 9B、4B：长解臂 − 短解臂 ≥ +5pp（MATH 5,000），区间不含 0 | 70% |
| LC-2 | 9B、4B：长解臂 − 训练前 0-shot 基线 ≥ −5pp（MATH-500），即基本不掉分 | 60% |
| LC-3 | 9B、4B：长解臂正常终止输出的平均长度 ≥ 600 token | 80% |
| LC-4 | 9B-Base：长解臂 − 短解臂 ≥ +5pp | 55% |

**事先约定的解读。** LC-1 与 LC-3 都成立：支持"写法决定水平"的解释。LC-3 成立而 LC-1 不成立：模型写长了但没有变好，解释不成立，掉分另有原因。LC-3 不成立：128 步没有让模型改变写法，这组对照没有检验到问题。
