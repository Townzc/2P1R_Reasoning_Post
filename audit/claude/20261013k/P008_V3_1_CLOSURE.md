## 新增的 3 条执行条款

### A1（高，代码）：8× 需要新的学习率规则；直接沿用会出错

`experiments/sft_allocation_midpoint/runtime.py` 中的 `lrs()` 写死了 256 步，即 16 步 warmup，然后余弦退火 240 步；`frozen_main_lrs` 还断言 `len == 256`。如果直接把公式延长到 2,048 步，余弦会越过半个周期又升回去：在 i ≈ 495 时回到 1e-4，最后一步约为 6e-5，而不是 1e-5。

建议把规则定义在归一化时间上：

```python
w = U // 16
lr_i = 1e-4 * (i + 1) / w                                         # i < w
lr_i = 1e-5 + 0.45e-4 * (1 + cos(pi * (i - w + 1) / (U - w)))    # i >= w
```

我已验证：U = 256 时，这个公式与现有冻结向量**逐位相等**（max |Δ| = 0.0）；U = 2048 时，warmup 为 128 步，最后一步为 1e-5。这条规则必须在任何学生结果出来之前写入协议，并对 U ∈ {256, 2048} 加单元测试。它是"联合扩量路径"训练契约的一部分（呼应 F2：优化路径不同，不能说只改变了答案数量）。
