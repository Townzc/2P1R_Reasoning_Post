# 审计意见 20261014az：MATH 教师上下文超长的处理（针对预注册草案 20261014ay v2）

- 时间：2026-10-14 11:20 PDT
- 来源：负责人转述的 Codex 数据预检。MATH 训练集 7,500 题中有 7 题，完整输入加上 1,024 token 生成上限后最长 2,706 token，超过教师 2,048 的上下文。Codex 提议：只把教师采购（procurement）的上下文改为 3,072，学生训练和终点评测仍为 2,048。
- **证据状态**：预检本身还没有推送到仓库，我无法核对“7 题、2,706 token”这两个数字。
- 结论：**不建议改为 3,072。建议在生成之前，按输入长度把这 7 题排除。**

## 1. 为什么不建议改成 3,072

1. **改了也用不上**。2,706 − 1,024 = 1,682，说明这几题的教师输入约 1,700 token。学生训练的上限仍是 2,048，所以这些题的教师答案只要超过约 350 token，训练样本就放不下，只能截断或丢弃。也就是说，我们会花钱买到大部分无法使用的答案。
2. **会造成静默不一致**。采购和训练用两个不同的长度上限，等于在 P008 协议之外新增一个参数，还会多出一类“已采购、不可训练”的状态，后续的成本核算、D 臂的同成本计算、P_nat 的构造都要额外处理。
3. **影响可以忽略，而排除更干净**。7 / 7,500 ≈ 0.09%。排除规则只依赖输入长度，不看标签，也不看任何输出，因此不会带来按结果挑选的偏差。

## 2. 建议的修正条款（需负责人直接批准）

> **§4 P2 补充**：MATH 训练池先按教师的完整输入长度过滤：若 教师 prompt token 数 + 1,024 > 2,048，就在任何生成之前排除该题。排除的题号、长度和数量要记录在准入材料里。教师上下文保持 2,048 不变。

## 3. 同一类问题，需要 Codex 在 A1 前一并报告

| 检查项 | 要求 | 不满足时的处理（预先规定） |
|---|---|---|
| 训练样本长度 | 每条训练样本（学生 prompt + 教师答案 + EOS）≤ 2,048 学生 token。S1 应自动满足，因为学生 prompt 比带模板的教师 prompt 短，且答案 ≤ 1,024；S2 换了分词器，必须实测 | 超长的样本直接丢弃、不截断，并在训练前计数；丢弃比例 > 1% 时停下报告 |
