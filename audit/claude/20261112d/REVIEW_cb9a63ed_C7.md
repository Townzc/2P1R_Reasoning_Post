## 2. 核对要点

- **pass@k**：每题 8 次采样（T=0.7，top-p 1.0，上限 4,096）。pass@1 = 答对次数 / 8，pass@8 = 8 次里是否至少对 1 次，再对 500 题取平均。缺失或重复的采样会报错。与计划 §5.4 一致：base 用 4 个示例，Instruct 用 0-shot。
- **训练前测试基线**：4-shot（主口径）和 0-shot（次口径），四个模型都测，greedy。与修订 2 一致。示例作为对话轮次放入训练模板。
- **NLL**：
  - 用固定版本 LLaMA-Factory 的预处理得到输入和标签，并逐条断言"输入 = 提示 + 解"、"提示部分的标签全是 −100"。
  - 损失只算在教师解和模板结束符上；第一个位置是被屏蔽的提示 token，所以因果移位不会丢掉任何一个目标 token。
  - 每次前向只放一条解，不填充、不截断；汇总时按 token 数加权。
  - 条件是 0-shot 的训练序列前缀。也就是说，这个量**等于该模型在这批留出解上、训练第 0 步时的损失**。
- **解读上的限制**（报告里要写）：
  - 对 base 模型，0-shot 的对话模板本身就是没见过的格式，所以它的 NLL 同时包含"不熟悉格式"和"不会做题"两部分。pass@8（base 用 4-shot）受格式影响小。两个指标要一起看。
  - 留出题上的 pass@8 对 base 和 Instruct 用了不同的条件（4-shot 对 0-shot），这是计划里登记的。检验 H1 时，同时报告条件一致的那个量：四个模型都有的 4-shot greedy 测试基线。
