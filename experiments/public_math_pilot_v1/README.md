# Public math pilot v1 — preparation and bounded engineering preflight

The owner requested this finite public-benchmark plan on 2026-09-17. It supersedes the prior pause only for the named phase. All E040–E043 results and old ledgers remain historical and unchanged. This phase starts from the fresh public Qwen2.5-Math-1.5B base, with full-parameter tuning; no earlier synthetic-task adapter is inherited.

The registered primary arms are E044/SFT, E045/DFT, E046/TrimSFT and E047/QDW_v0, with Base E044-B0. Each formal arm requires the same frozen 4096 questions and 128 updates. Step64 is diagnostic only. The complete evaluation requires 31203 generations and QDW requires 8192 sequence forwards. Optional shuffled masks, 7B, seed29 and full CFT GPU annotation are excluded.

Implemented CPU modules cover exact tokenization, detached losses, all-question deduplication/decontamination, official Qwen parsing/judging, and recovery logic across two storage volumes (validated on tiny CPU/fault tests; full-Qwen GPU recovery is unrun). `preflight.py` implements only the finite engineering profile; the formal training/evaluation orchestrator is not yet implemented or admitted. Source is published before any model invocation. The source guard binds the actual executed closure and frozen inputs to the published commit and an independently verified inventory SHA.

The unexecuted preflight is designed to run at most five planned nonformal optimizer updates: one per arm on the fixed train-profile32 and an additional TrimSFT update using actual longest frozen references. All start from public base by arm and all smoke states are discarded. When executed, the SFT smoke is designed to verify a real full-parameter Adam/RNG save/load roundtrip before explicitly discarding only this engineering state. This GPU roundtrip has not been run. Fixed32 full/blank base annotations and first32 Base-dev greedy outputs, if completed, retain exact reuse identities and consume the phase's shared durable physical ledger. Failures stay charged; no failed output becomes a mathematical error. The global nonformal cap is eight, including reservations before failures.

The source plan caps preflight at 1h/CNY10 and the proposed complete phase at 12h/CNY120, each subject to lower effective resources and a 15-minute shutdown/export reserve. The server was shut down before any model process was launched. CPU qualification/scoring repairs consumed the preparation window; GPU preflight, longest-reference memory and throughput remain unmeasured. The present measured raw checkpoint export route already exceeds the effective available time after the required 1.3 factor, before training/evaluation. Consequently a successful engineering preflight does **not** authorize or admit the main grid. See the resource report. No account recharge, additional machine or benchmark reduction is performed.
