## 本轮公共数学实验的可用结论

共同模型为 Qwen2.5-Math-1.5B **Base**。SFT、DFT、TrimSFT、QDW-v0 使用相同的 4,096 条 NuminaMath-CoT 训练题、128 次更新和训练 seed 17；Base 为未训练参照。固定第 128 步为科学终点，第 64 步仅用于开发诊断。

QDW-v0 比较冻结基础模型在“有问题／去掉问题、保留同一参考答案前缀”条件下的正确 token 对数概率。按已冻结规则选出符合条件位置中的最高 10%，给这些位置 5 倍软权重，并归一化回答总权重；最终答案位置不进入所选集合。这是一个问题依赖性的代理信号，尚不能称为已识别出的因果关键 token、严格互信息或“第一个决策”的直接迁移。

全部 GSM8K 的已完成结果如下。每个状态保留全部 1,319 题，未决判分为零。

| 状态 | 正确数／1,319 | Greedy 准确率 |
|---|---:|---:|
| Base | 495 | 37.53% |
| SFT | 1,068 | 80.97% |
| DFT | 1,046 | 79.30% |
| TrimSFT | 1,009 | 76.50% |
| QDW-v0 | 1,080 | 81.88% |

QDW 相对 DFT 为 **+2.58pp**，97.5% 题目配对 bootstrap 区间 **[+0.30,+4.85]pp**；相对 TrimSFT 为 **+5.38pp，[+2.88,+7.88]pp**。相对普通 SFT 仅为 **+0.91pp**，95% 区间 **[−0.99,+2.81]pp**。因此，“超过两种加权基线”与“稳定超过普通 SFT”是两个不同强度的陈述，后者目前没有得到支持。

这些是辅助 benchmark 的描述性结果，不能代替 MATH 主比较。区间仅反映题目抽样，不包含训练种子不确定性。Base 有大量解析／长度上限失败，故相对 Base 的大幅提升也不能全部解释为数学推理能力提升。精确计数、逐题数组和区间见 [GSM8K 完整辅助结果](GSM8K_COMPLETE_PARTIAL_RESULTS.json)。

## 与已有论文的关系

- [DFT](https://arxiv.org/html/2508.05629v3)：已经执行的直接对手，按正确 token 概率加权。
- [TrimSFT](https://arxiv.org/html/2609.09707v1)：已经执行的直接对手，按 logit 差距调整 token 权重。当前使用论文公式实现，不应称为完整官方代码复现。
- [CFT](https://arxiv.org/html/2510.10974v1)：重要但尚未执行的直接对手，通过 token 替换和后续 rollout 识别关键位置。它的数据筛选与标注成本需要单独控制；已有 [复现契约](../../experiments/public_math_pilot_v1/CFT_REPRO_CONTRACT.md) 不等于已完成比较。
- [IFD](https://arxiv.org/abs/2308.12032)：有／无指令条件的损失比较已有先例。新颖性需要体现于 token 层设计、受控证据和成本，而非仅提出这种条件对比。

本轮控制了我们自己的训练预算，但没有复现各原论文的数据量和整套配方。不能把本轮分数直接与论文表格相减宣称超越；参见 [文献与 pilot 口径](../../experiments/public_math_pilot_v1/PAPER_REFERENCE_TABLE.md)。也不能因为当前方法动机来自算术干预，就预先认定它解决了公共数学中的同一个机制问题。

## 资源、失败和已积累的实验能力

四组训练的进程记录累计 3,714 秒，约 62 分钟，包含 checkpoint 保存、故障前执行及恢复，排障间隔另计。准备进程 2,521 秒同时包含 mask 计算和 Base-dev 生成，不能全算为标注成本。评估需要逐 token 自回归生成 31,203 条答案，构成本轮主要耗时；CPU 判分与 GPU 生成并行。

截至检查，双卡最近约半小时平均利用率为 **97.78%／98.76%**，没有新 traceback、CUDA OOM 或 cgroup OOM。25 个已完成 MATH batch 平均约 **748 秒**、最大约 **778 秒**。高利用率说明两卡在工作，尚未证明现有后端、批处理和 padding 的单位有效输出成本最优。不得把未测过的硬件或推理引擎加速倍数写成结论。

必须随结果一起保留两次事故：

1. 首个 GSM128 batch CUDA OOM：128 次生成尝试丢失，后来仅按明确恢复授权重做。最终逻辑目标仍为 31,203，物理生成上限为 31,331。
2. TrimSFT checkpoint 保存前因干净文件缓存触发内存准入失败：32 次未提交更新丢失。最终科学剂量为 512 次，物理完成记录为 544 次。恢复了模型、AdamW、RNG 和原始代码，但 GPU 重放不是逐位一致，原因未隔离；不能隐去或说成完全精确恢复。

现有能力包括：冻结数据与源代码、固定终点、按题保留输出与 RNG、真实物理尝试记账、两卡独立 worker／锁、断网不受影响的 tmux 执行、CPU 判分、配对不确定性和服务商关机确认。这些使后续研究可审计，本身不构成方法创新。

四组最终完整恢复状态和八个科学权重文件共 **106,270,841,556 字节**。00:23 UTC 曾在服务器全量重算哈希；03:33 UTC 再次核对 12 个文件存在、大小及 manifest 身份一致，后一次没有重复读取全部二进制。大文件按现行授权留在服务器。数据盘约 82.38 GiB 可用。旧 E015 唯一权重的独立完整备份义务仍未解决，不能清理其实例或卷。

## 长期研究建议：先选清问题，再增加实验

长期分支 LT001 原先关注：**在相同训练剂量与真实采集预算下，获得第一条／更多可用答案的成本，会不会改变问题广度与答案深度的最佳分配？** 当前 QDW pilot 关注：**在相同训练数据与剂量下，问题依赖的 token 权重是否改善学习？** 两者可以相互启发，但有不同的干预、比较对象和核心证据，不能直接合并为已经完成的同一个贡献。

我的建议是把本轮完整结果作为选题输入，而非预先承诺一个正面结论：

| 待决方向 | 最有价值的下一步证据 | 需要避免的误读 |
|---|---|---|
| 继续研究监督位置 | 在开发数据上检验 QDW 权重与普通难度、相对位置、数字／操作符等特征的关系；随后用预算明确的随机位置、难度匹配或位置匹配对照区分解释。 | 仅在 DFT／TrimSFT 上领先，就假定问题依赖信号有独特贡献；忽略普通 SFT。 |
| 建立可复现的公共任务效果 | 完整报告这次预定主结果；选定配方后安排独立训练种子和新确认数据，再决定是否做 CFT 与第二模型。 | 用反复查看的 MATH／GSM 测试分数选择新超参数，或只复跑最有利的比较。 |
| 回到真实采集成本与分配 | 先设计有失败、重复、零产出题目的完整采集事件记录；在新题池和未用于选择的分配规模上验证策略。 | 把现成缓存大小、假设定价或 QDW 的 mask 成本，当成真实问题／答案采集成本结论。 |

上述均为提案，本次没有新增模型调用。若完整 MATH 无清晰优势，优先解释普通 SFT／DFT／TrimSFT 与 QDW 的差异和边界；保留负结果，避免围绕同一测试集持续调整到出现优势。

算力安排建议分成固定的小规模开发筛选、候选冻结后的完整验证、证据充分后的扩展复现。完全相同的模型／数据／终点／评估契约可复用既有基线输出；配置变化时需要重新核对公平比较。推理后端和 batch 工程优化应另做有预算的资格验证，记录有效 token／秒、每千条答案成本及正确性边界，再用于新的实验契约。本轮运行中的评估不改设置。

训练后不必让两张 A800 等待人工分析。CPU 与文档工作在本地完成，需要 GPU 时运行准备好的有限队列，之后及时关机。后续每阶段先列出要回答的问题、最大生成量、预期 GPU 小时与停止条件。venue 选择应跟随最终贡献和经核对的征稿要求；这里不设未核验的投稿日期，也不创建新的自动执行计划。
