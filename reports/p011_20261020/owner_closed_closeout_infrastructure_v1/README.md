# Original-app closeout after a local infrastructure failure

The completed baseline's first collector exited before named-record reads or archive transfer because this backend returned SUCCESS with an empty task_id. The per-call adapter is withdrawn; its original evidence remains immutable. A follow-up read-only AppGetObjects diagnostic was unsupported by the backend and produced no saved result. Neither operation reran a model.

Use the new closed_io adapter only after the original app has exited. It preserves the original STOPPED/zero-container proof, exact original receipt, full oracle and scorer. The baseline gets the owner's one infrastructure-only retry in a new directory; any prior data download or another failure is rejected. Other jobs get their first collector. Original source63 and source110 active runtime files are unchanged.

Score time is the smaller of the original maximum and time remaining before the original absolute cutoff, reserving five seconds for owned cleanup. This removes a predicted-minimum-duration rejection; it does not change labels, scorer rules or deadline. Use Modal environment for collect, data_pipeline environment for audit, math_verify environment for first score, analysis environment for contrasts. Never invoke the withdrawn per-call adapter again. No production closeout retry has run at publication.
