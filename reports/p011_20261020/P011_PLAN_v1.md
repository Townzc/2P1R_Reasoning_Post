## 1. 实验 A：OpenThoughts3 数学子集的 P×K 网格

### 1.1 数据构建（CPU；A1 审计）

1. **下载**：`open-thoughts/OpenThoughts3-1.2M`，固定并记录 HF commit sha；只取 `domain == math` 的行。逐文件记录 SHA。
2. **还原父题**：父题键 = Unicode NFKC 规范化 + 去除首尾空白后的 user 文本。每个父题记录：行数、来源、difficulty。
   - 行数不是 16 的父题单独列出，不进入候选池。
   - 不同 source 下题干完全相同的，算作同一父题。
3. **长度过滤**：用候选学生的分词器（Qwen2.5 系列，1.5B 与 3B 相同）把 chat 格式化后的 prompt+response 编码。**一个父题的 16 条回答必须全部 ≤ 16,384 token**，否则整个父题剔除。不允许只剔除单条回答，以免 K 越大的格越偏向容易的题。
   - 报告：剔除比例；保留题与剔除题的 difficulty 分布。
4. **完整性**：回答末尾区域（`</think>` 之后；没有 `</think>` 就看全文最后 2,000 字符）必须含 `\boxed{`。规则同 3，按父题整体判断，并报告剔除比例。
   - **OT3 原数据不验证答案正确性。我们也不验证，必须披露。**
5. **去污染**：父题与 MATH-500、AIME24、AIME25、AMC23 的题干做 13-gram 重叠检查（规范化后）。命中的父题在抽样前剔除，并报告数量。
6. **抽样顺序（嵌套）**：
   - 候选父题按 `Random(20261020).shuffle`（输入先按父题键排序）打乱，取前 4,096 个。
   - 每个父题的 16 条回答按 `Random(sha256(父题键+'p011')[:16]).shuffle` 打乱，取前 K 条。
   - 由此保证 P 嵌套：256 ⊂ 1024 ⊂ 4096；K 嵌套：1 ⊂ 2 ⊂ 4 ⊂ 8 ⊂ 16。
7. **chat 格式**：用学生模型自带的 chat template。系统提示保持 template 默认，不另加。只监督 assistant 部分 + `<|im_end|>`。

| 编号 | (P, K) | N | 所属轴 |
|---|---|---:|---|
| A1 | (256, 1) | 256 | K 轴、P 轴 |
| A2 | (256, 2) | 512 | K 轴 |
| A3 | (256, 4) | 1024 | K 轴 |
| A4 | (256, 8) | 2048 | K 轴 |

**基线**：所选学生（以及冒烟中其他臂）的 Instruct 模型，不训练，按同一协议评测。

### 1.3 训练（每格固定计算量）

- **固定 token 预算**：B = A7 全部监督 token 恰好过一遍的总量（构建时算出并冻结）。每一格都训练恰好 B 个监督 token，小格因此会多轮重复。
  - 每条回答至少训练一次；每格内各条回答的暴露次数相差 ≤ 1，沿用 P009 q/q+1 的思路。
- **批次与优化**：
  - 每次更新的监督 token 预算约 64k，更新次数 U = ⌈B/64k⌉，冻结后所有格相同。
  - 不截断，不打包（packing），按长度分桶以减少 padding。
  - seed 17。
  - AdamW，warmup 5%，余弦退火到峰值的 10%。
- **三个冒烟臂**：

  | 臂 | 学生 | 方式 | 峰值 LR |
  |---|---|---|---|
  | S-L15 | Qwen2.5-1.5B-Instruct（锁定 revision） | LoRA r64 / α128 / dropout 0，覆盖 q,k,v,o,gate,up,down | 1e-4 |
  | S-F15 | Qwen2.5-1.5B-Instruct | 全参微调 | 1e-5 |
  | S-L3 | Qwen2.5-3B-Instruct（锁定 revision） | LoRA r64，配置同 S-L15 | 1e-4 |

- **LR 依据**：全参 1e-5 来自 Li et al. 2025 的 <14B 设置；LoRA 取约 10 倍，依据 LoRA Without Regret。**不做 LR 搜索**，在报告中披露。
- **最大长度**：16,384 + prompt；开梯度检查点。

### 1.4 评测（A 与 D 共用）

- **引擎**：vLLM 0.11，bf16，chat template。生成上限 16,384 个新 token。
- **主指标**：MATH-500 采样 4 次（T=0.6、top-p 0.95、seed 0–3），取平均 pass@1。
- **次指标**：
  - MATH-500 greedy；
  - AIME24 + AIME25（共 60 题）、AMC23（40 题）各采样 8 次。这三个只做描述性报告，不做判读。
- **评分**：P1 冻结的 math-verify 评分器，SHA 不变。
  - 唯一改动：答案区域取 `</think>` 之后的文本，没有 `</think>` 就用全文，然后取最后一个 `\boxed{}`。这个改动作为新代码送审。
  - 被截断的回答一律判错，并单独统计截断数。
- **统计**：题目层面配对 bootstrap，10,000 次，seed 20261021，线性分位数。

## 2. 冒烟门槛与学生选择（规则冻结）

三个臂在 A7 上同时训练、评测，基线评测也同时进行。

**通过条件**（三条都要满足）：
1. MATH-500 采样回答中，以 EOS 正常结束的比例 ≥ 70%；
2. 平均 pass@1 ≥ 同尺寸 Instruct 基线 − 10pp；
3. 训练与评测无技术失败。

**选择规则**
1. 通过的臂里，取平均 pass@1 最高的；若有更便宜的通过臂与它相差 ≤ 3pp，改选更便宜的。"便宜"按冒烟实测的每格费用比较。

3. 选中的臂跑 A1–A6 和 A8，A7 直接复用冒烟结果，不重跑。
4. 如果选中 S-L3，并且按实测费用全网格会超出 A 的子上限，就按削减顺序（§7）减格。

**执行与披露**

## 8. 预先冻结的判读（探索性）

"明显"的标准：差值 ≥ 3pp，且 95% CI 下界 > 0。主指标为 MATH-500 的 4 次采样平均 pass@1。

| 记号 | 定义 |
|---|---|
| Δ_K^A(K) | A(256,K) − A(256,1) |
| Δ_P^A | A(4096,1) − A(256,1)，以及 A(1024,1) − A(256,1) |
| Δ_diag^A | A(4096,1) − A(256,16)，以及 A(1024,4) − A(256,16) |
| Δ_TK | [B3 − B1] − [P010 T0.8 (400,8) − (400,1)] |
| Δ_T^CS | C2b − C2a |
| Δ_T^D | D2 − D1 |

| 结果 | 含义 |
|---|---|
| Δ_P^A 或某个 Δ_K^A 明显 | 长链设定下数据确实起作用，分配问题成立 |
| Δ_diag^A 明显为正 | 同样数量下，"更多题"优于"更多解"，与 P008/P010 的 Δ_diag 方向一致 |
| Δ_diag^A 明显为负 | 长链设定下"多解"更划算，与短链相反 |
| A 全部 \|Δ\| < 2pp | 小预算下长链学习不敏感；算力申请改为扩大训练预算 |
| Δ_TK 明显为正 | 支持"高温让多答案有用" |
| C1 中 T72 的 NLL 明显更高（描述性） | 与可学性差距的解释相容 |
| Δ_T^CS 接近 0，而原 Δ_T < 0 | 原来的负值可能来自选题偏差 |
| Δ_T^D 任一方向明显 | 长链设定下教师来源有影响（参照 Tian et al. 2025） |
