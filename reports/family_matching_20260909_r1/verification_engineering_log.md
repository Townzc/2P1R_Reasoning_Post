# Independent verification engineering record

This log records verifier execution and implementation checks. It is not another
C009 matching run, a new solution enumeration or a model experiment.

## Initial verifier rejection

The first real-report invocation failed at the source-scope guard:

```text
ValueError: Unexpected published input scope
```

This was a **verification engineering failure**, not a failed C009 scientific
result or an invalid C009 input. The verifier's initial explicit source whitelist
omitted `scripts/audit_legal_support.py`, which the final C009 execution manifest
correctly included. The report summary had been read, but rejection occurred
before reading the tokenized solution inventory or loading the tokenizer.
No independent verification report was generated by this failed invocation.
An exact wall-clock timestamp and elapsed time for this invocation were not
recorded; neither is reconstructed here.

The correction added this known, in-scope source to the whitelist. Published
source bytes still had to match every recorded SHA-256 at C009's execution
commit. No source-hash check was disabled, and the C009 artifacts were unchanged.

## Successful verification

The corrected invocation passed in **21.553543207992334 seconds**, as recorded in
`independent_verification.json`. It independently checked all 25,846 ordered
records, all 256 training problems, complete per-problem Hall/structure-flow
stages and policy simulations, 4,491 problem witnesses across 681 discovered
shared keys, and the single four-problem schedule block. The verification
receipt's source SHA-256 matches the current `scripts/verify_family_matching.py`.

The original C009 key search remains incomplete. These checks certify the
published feasible witnesses; they do not independently enumerate every possible
shared key, certify maximum packing, or authorize GPU training.

## Padding and synthetic tests

The actual constructed block has **zero padding** in every update and condition.
Each condition has four updates, 16 presentations, 1,024 supervised tokens and
1,824 processed nonpadding tokens for this one-cycle CPU schedule witness.

The verifier's synthetic nonzero-padding fixture deliberately uses sequence
lengths 100, 102, 104 and 106 with microbatch size two. It therefore has **four
padding tokens per update and 16 per condition/cycle**. The fixture verifies that
the checker calculates padding rather than assuming it is zero; its values are
not measurements of C009's actual block. All **19** verifier unit tests passed.
